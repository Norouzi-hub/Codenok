# سامانهٔ مدیریت پرونده‌های کمیتهٔ انضباطی

یک برنامهٔ کاملاً محلی برای ثبت، جستجو، پیگیری و گزارش‌گیری از پرونده‌ها.
**بدون نصب، بدون سرور، بدون اینترنت** — فقط یک فایل که در مرورگر باز می‌شود.

---

## شروع سریع

۱. فایل `dist/parvandeha.html` را روی رایانهٔ خود ذخیره کنید (مثلاً در `Documents`).
۲. روی آن دابل‌کلیک کنید تا در کروم، اج یا فایرفاکس باز شود.
۳. بار اول، ۳۱ پروندهٔ نمونه از فایل اکسل شما به‌صورت خودکار وارد می‌شود.
۴. **مهم:** دکمهٔ ⚙ (تنظیمات) ← بخش «ذخیره‌سازی» ← **اتصال به فایل دیتابیس**.
   یک محل و نام برای فایل انتخاب کنید (مثلاً `parvandeha-db.json`).
   از این پس هر تغییری خودکار روی همان فایل روی دیسک شما نوشته می‌شود.

روی ویندوز و مک یکسان کار می‌کند. فایل را می‌توانید روی فلش یا OneDrive هم بگذارید.

## چه چیزهایی دارد

| قابلیت | توضیح |
|---|---|
| **همهٔ ۶۹ فیلد** | دقیقاً همان ستون‌های فایل اکسل، دسته‌بندی‌شده در ۷ تب بر اساس مرحلهٔ پرونده |
| **جستجوی آنی** | بدون رفرش صفحه؛ روی همهٔ فیلدها، مقاوم به «ی/ک» عربی و فارسی و ارقام فارسی |
| **فیلتر ترکیبی** | وضعیت، کارشناس، سال، نوع پرونده، واحد سازمانی، مرجع گزارش‌دهنده و بازهٔ تاریخ |
| **تاریخچهٔ کامل** | هر تغییر، فیلد به فیلد، با مقدار قبلی و جدید، تاریخ شمسی و نام کاربر |
| **تایم‌لاین گردش‌کار** | رویدادهای مرحله‌ای (ورود، ارجاع، استعلام، دعوت، کمیته، ابلاغ) خودکار ساخته می‌شوند |
| **تقویم شمسی** | ورود تاریخ با تقویم یا تایپ سریع؛ همهٔ تاریخ‌ها یکدست ذخیره می‌شوند |
| **خروجی اکسل** | فایل `.xlsx` واقعی با دو شیت: پرونده‌ها و تاریخچهٔ تغییرات |
| **خروجی SQLite** | فایل `.sqlite` استاندارد، قابل باز کردن با هر ابزار دیتابیس |
| **چاپ** | برگ پروندهٔ A4 رسمی (با جای امضا) و چاپ فهرست با ستون‌های دلخواه |
| **ورود از اکسل** | فایل اکسل را وارد کنید؛ پرونده‌های تکراری به‌روزرسانی و تغییرشان ثبت می‌شود |
| **پشتیبان‌گیری** | خروجی/ورودی کامل JSON برای جابه‌جایی یا بازیابی |
| **گزارش‌ها** | داشبورد تحلیلی با نمودار، تحلیل خودکار و خروجی اکسل/چاپ — پایین‌تر |
| **مستندات** | نامه، حکم، رأی و دعوت‌نامه در پوشهٔ واقعی هر پرونده روی دیسک — پایین‌تر |

### میان‌برها

| کلید | کار |
|---|---|
| `Ctrl` + `F` | رفتن به جعبهٔ جستجو |
| `Ctrl` + `N` | پروندهٔ جدید |
| `Ctrl` + `S` | ذخیرهٔ پرونده (در فهرست: گرفتن پشتیبان) |
| `Ctrl` + `G` | رفتن به گزارش‌ها |
| `Esc` | بستن پرونده / تقویم |

## مستندات پرونده

هر پرونده یک تب **«مستندات»** دارد. فایل‌ها در یک **پوشهٔ واقعی روی دیسک شما**
ذخیره می‌شوند، نه داخل مرورگر:

```
مستندات کمیته/
  1404308 - غلامستان اینده/
    1404-07-15 - نامهٔ وارده - 1404-11133-429-م.pdf
    1404-08-20 - استعلام حراست - 112-1404-134-12.pdf
    1405-05-04 - رأی کمیته - رأی جلسهٔ ۱۱.pdf
    1405-05-04 - رأی کمیته - رأی جلسهٔ ۱۱ - نسخه 2.pdf
```

یک بار در تنظیمات پوشهٔ ریشه را انتخاب می‌کنید؛ زیرپوشهٔ هر پرونده خودکار ساخته
می‌شود و نام فایل از تاریخ، نوع سند و شمارهٔ نامه ساخته می‌شود.

| قابلیت | توضیح |
|---|---|
| **افزودن سند** | کشیدن‌و‌رها کردن یا انتخاب فایل؛ تاریخ و شمارهٔ نامه از نام فایل حدس زده می‌شود |
| **نوع سند** | نامهٔ وارده/صادره، گزارش بازرسی، دعوت‌نامهٔ جلسه، دفاعیهٔ کتبی، استعلام و پاسخ حراست، صورت‌جلسه، رأی کمیته، نامهٔ ابلاغ، بازگشت ابلاغ، حکم کارگزینی، مدارک هویتی (قابل ویرایش در تنظیمات) |
| **نسخه‌بندی** | نسخهٔ جدید یک سند، نسخهٔ قبلی را پاک نمی‌کند؛ زیر همان سند بایگانی می‌شود |
| **پویش پوشه** | اگر با اسکنر مستقیم داخل پوشهٔ پرونده اسکن کنید، برنامه فایل‌های ثبت‌نشده را پیدا و با یک کلیک ثبت می‌کند |
| **تایم‌لاین** | هر سند در تاریخِ خودش کنار رویدادهای گردش‌کار می‌نشیند |
| **تاریخچه** | افزودن، نسخهٔ جدید و حذف هر سند در تاریخچهٔ پرونده ثبت می‌شود |
| **جستجو** | نوع و عنوان سند در جستجوی سراسری پیدا می‌شوند |
| **هم‌نام کردن پوشه** | اگر شماره یا نام پرونده عوض شود، با یک دکمه پوشه و فایل‌ها به نام تازه منتقل می‌شوند |
| **گزارش** | «رأی صادرشده بدون سند رأی»، «ابلاغ بدون سند ابلاغیه» و «پرونده‌های بدون هیچ سند» به یافته‌ها اضافه شده‌اند |
| **چاپ** | برگ پرونده یک بخش «مستندات پیوست» دارد |

### نکته‌های مهم

* **فقط کروم و اج.** فایرفاکس این API را ندارد و تب مستندات در آن پیام می‌دهد.
* نویسه‌های ممنوع ویندوز (`\ / : * ? " < > |`)، نام‌های رزرو (`CON`, `PRN`, …)
  و نقطه/فاصلهٔ انتهایی خودکار پاک‌سازی می‌شوند. حروف فارسی مشکلی ندارند.
* فایل‌ها **کپی** می‌شوند، نه منتقل؛ مرورگر اجازهٔ حذف فایل مبدأ را ندارد.
* برنامه مسیر کامل پوشه را نمی‌داند (محدودیت امنیتی مرورگر)، ولی چون خودتان
  انتخابش کرده‌اید در فایل‌منیجر هم در دسترستان است.
* **مرورگر پس از هر بار بسته شدن یک تأیید تازه می‌خواهد.** لازم نیست پوشه را
  دوباره انتخاب کنید؛ برنامه دکمهٔ «تأیید دسترسی» نشان می‌دهد، یک کلیک کافی است.
* فایل‌ها در پشتیبان JSON نمی‌آیند (فقط فرادادهٔ آنها). از پوشهٔ مستندات جداگانه
  نسخهٔ پشتیبان بگیرید.

## بخش گزارش‌ها

از نوار بالا روی «گزارش‌ها» بزنید (یا `Ctrl` + `G`). بالای صفحه یک ردیف فیلتر است
که **همهٔ** نمودارها، سنجه‌ها و جدول‌های زیرش را هم‌زمان برش می‌زند.

### بازهٔ زمانی

بازه دو بخش دارد: **روی کدام تاریخ** و **چه بازه‌ای**.

* **تاریخ مبنا:** تاریخ ورود به دبیرخانه (پیش‌فرض)، تحویل به کارشناس، طرح در
  کمیته، ابلاغ رأی، یا تاریخ نامهٔ گزارش. مثلاً برای «در سال ۱۴۰۵ چند رأی ابلاغ
  شد؟» مبنا را روی «تاریخ ابلاغ رأی» بگذارید.
* **بازه:** ماه جاری، فصل جاری، از ابتدای سال، ۳۰/۹۰/۱۸۰/۳۶۵ روز اخیر، و —
  مهم‌تر برای دادهٔ تاریخی — **هر سال و هر فصلی که واقعاً در داده‌های شما وجود
  دارد** (سال ۱۴۰۴، بهار ۱۴۰۴، تابستان ۱۴۰۴، …) و بازهٔ دلخواه.

زیر ردیف فیلتر، بازهٔ دقیقِ حل‌شده نوشته می‌شود، به‌همراه دورهٔ قبل که مقایسه با
آن انجام می‌شود، و تعداد پرونده‌هایی که آن تاریخ مبنا را ندارند و ناچار از برش
کنار گذاشته شده‌اند — عدد هیچ‌وقت بی‌صدا ناقص نمی‌ماند.

نمودار روند هم **تفکیک زمانی** دارد: ماهانه، فصلی، سالانه، یا خودکار (از روی طول
بازه انتخاب می‌شود تا محور شلوغ نشود).

وقتی از نمودار به فهرست پرونده‌ها می‌روید، همین بازه و همین تاریخ مبنا با شما
منتقل می‌شود تا عددها بخوانند. فهرست پرونده‌ها هم در نوار کناری‌اش همین انتخاب
«تاریخ مبنا» را دارد.

### چه چیزی گزارش می‌شود

| بخش | محتوا |
|---|---|
| **سنجه‌های کلیدی** | کل پرونده‌های برش، در جریان، مختومه، میانهٔ روز تا طرح در کمیته، قدیمی‌ترین پروندهٔ باز — با مقایسهٔ دورهٔ قبل وقتی بازه انتخاب شده باشد |
| **قیف گردش‌کار** | هر عدد یعنی «به این مرحله رسیده یا از آن گذشته»، پس همیشه نزولی است |
| **یافته‌ها و پیشنهادها** | تحلیل خودکار: پرونده‌های راکد بالای ۹۰ روز، رأی صادرشدهٔ بدون ابلاغ، استعلام حراست بی‌پاسخ، پروندهٔ بدون کارشناس، تاریخ‌های ناسازگار، شمارهٔ تکراری، افراد با بیش از یک پرونده، پرونده‌های ناقص، و هشدار گلوگاه زمانی |
| **روند زمانی** | ورودی در برابر مختومه، با تفکیک ماهانه/فصلی/سالانه |
| **نوع پروندهٔ مطروحه** | سهم هر نوع از کل |
| **وضعیت پرونده‌ها** | فراوانی هر وضعیت |
| **سن پرونده‌های باز** | سطل‌های ۳۰/۶۰/۹۰/۱۸۰ روز و بیشتر |
| **میانهٔ زمان هر مرحله** | میانه، میانگین، بیشینه و تعداد نمونه برای چهار گذرگاه گردش‌کار |
| **کارکرد کارشناسان** | تعداد کل/باز/مختومه و میانهٔ زمان رسیدگی هر کارشناس |
| **پراکندگی سازمانی** | واحد سازمانی، مرجع گزارش‌دهنده، نوع محل خدمت و ماهیت شغل |

**هر نمودار قابل کلیک است:** روی هر میله یا هر یافته بزنید تا همان پرونده‌ها در
فهرست باز شوند؛ نواری بالای فهرست نشان می‌دهد چه برشی فعال است و با یک کلیک
برداشته می‌شود. دکمه‌های «چاپ گزارش» (A4 با نمودارها، جدول‌ها و جای امضا) و
«خروجی اکسل گزارش» (هر جدول در یک شیت جدا) هم بالای صفحه‌اند.

### دربارهٔ نمودارها

بدون هیچ کتابخانهٔ نموداری — SVG درون‌خطی، حدود ۴۰۰ سطر کد در `src/js/charts.js`.
چند تصمیم که عمداً گرفته شده‌اند:

* **رنگ کار مشخصی می‌کند.** رستهٔ اسمی (واحد سازمانی، مرجع گزارش‌دهنده) همه یک
  رنگ می‌گیرند، چون طول میله خودش اندازه را نشان می‌دهد؛ رستهٔ ترتیبی (مرحلهٔ قیف،
  سطل سنی) رمپ تک‌رنگ روشن‌به‌تیره می‌گیرد؛ و فقط جایی که سری‌ها باید از هم
  تشخیص داده شوند (وارده/مختومه، انواع پرونده) رنگ‌های متمایز به کار می‌رود.
* **پالت با اسکریپت اعتبارسنجی شده، نه با چشم.** پالت رسته‌ای چهارتایی و رمپ
  ترتیبی پنج‌پله روی سطح سفید کارت‌ها همهٔ بررسی‌ها (باند روشنایی، کف اشباع،
  جدایی کوررنگی، کف دید عادی) را پاس می‌کنند.
* **هیچ مقداری پشت هاور قفل نیست.** هر کارت یک دکمهٔ «جدول» دارد که همان اعداد را
  به‌صورت جدول نشان می‌دهد؛ تولتیپ و برچسب مستقیم فقط کمک‌اند.
* **هیچ نموداری دو محور عمودی ندارد** و برچسب‌ها با اندازه‌گیری واقعی متن جا داده
  می‌شوند تا هرگز بریده نشوند یا از کادر بیرون نزنند.
* شدت هشدارها همیشه با **آیکن و برچسب متنی** همراه است، نه فقط رنگ.

## دربارهٔ ذخیره‌سازی داده‌ها

داده‌ها در **IndexedDB** مرورگر نگهداری می‌شوند (سریع و ایندکس‌دار). چون این فضا
متعلق به پروفایل مرورگر است، اگر «پاک کردن داده‌های مرورگر» انجام شود از بین می‌رود.
به همین دلیل:

* در **کروم و اج** برنامه می‌تواند مستقیم روی یک فایل روی دیسک شما بنویسد
  (تنظیمات ← اتصال به فایل دیتابیس). این کار را حتماً انجام دهید — نوار بالای
  برنامه تا وقتی وصل نشده‌اید هشدار می‌دهد.
* در **فایرفاکس** این قابلیت وجود ندارد؛ هر از چندی دکمهٔ «پشتیبان» را بزنید.
  برنامه بعد از هر ۲۵ تغییر یادآوری می‌کند.

نشانگر وضعیت ذخیره‌سازی همیشه گوشهٔ بالای صفحه دیده می‌شود.

## ساختار پروژه

```
src/
  index.html          صفحهٔ اصلی (نسخهٔ توسعه، فایل‌ها جدا)
  css/app.css         استایل‌ها، شامل استایل چاپ
  js/fields.js        اسکیمای ۶۹ فیلد و لیست‌های کشویی — خودکار ساخته می‌شود
  js/seed.js          داده‌های اولیه از فایل اکسل — خودکار ساخته می‌شود
  js/util.js          ابزارها: یکدست‌سازی متن فارسی، DOM، مودال، توست
  js/jalali.js        تبدیل و قالب‌بندی تاریخ هجری شمسی
  js/store.js         IndexedDB + ذخیرهٔ خودکار روی فایل دیسک
  js/model.js         پرونده‌ها، تاریخچه، جستجو، فیلتر و آمار
  js/datepicker.js    تقویم شمسی
  js/xlsx.js          نوشتن و خواندن xlsx بدون کتابخانهٔ بیرونی
  js/sqlite.js        خروجی SQLite (با sql.js جاسازی‌شده)
  js/charts.js        نمودارهای SVG درون‌خطی و پالت اعتبارسنجی‌شده
  js/report.js        محاسبهٔ سنجه‌ها، روندها و یافته‌های گزارش
  js/docs.js          مستندات: پوشه روی دیسک، نام‌گذاری امن، نسخه‌بندی، پویش
  js/ui.*.js          نماهای فهرست، فرم، مستندات، گزارش، چاپ و تنظیمات
  js/app.js           راه‌اندازی، نوار بالا، میان‌برها
  vendor/             sql.js (موتور SQLite)
tools/
  gen_data.py         ساخت fields.js و seed.js از فایل اکسل
  build.py            ساخت نسخهٔ تک‌فایلی در dist/
  test/smoke.js       تست خودکار در کرومیوم روی file://
  test/docs.js        تست مستندات با پوشهٔ ساختگی درون‌حافظه‌ای
dist/
  parvandeha.html     ← فایل نهایی؛ همین را استفاده کنید
```

### ساخت دوباره

```bash
python3 tools/gen_data.py <فایل اکسل>   # فقط وقتی ساختار ستون‌ها عوض شود
python3 tools/build.py                   # ساخت dist/parvandeha.html
node tools/test/smoke.js                 # تست خودکار (نیازمند playwright)
node tools/test/docs.js                  # تست مستندات
```

## تصمیم‌های فنی

* **چرا تک‌فایل؟** شرط اصلی «هیچ نصبی» بود. سرور محلی نیازمند نصب Node یا Python
  است؛ این فایل فقط به مرورگر نیاز دارد.
* **چرا کتابخانهٔ بیرونی نداریم؟** برای خروجی اکسل به‌جای کتابخانهٔ ~۹۰۰ کیلوبایتی،
  یک نویسندهٔ کوچک ZIP + SpreadsheetML نوشته شده است. تنها وابستگی جاسازی‌شده
  `sql.js` است که فقط هنگام گرفتن خروجی SQLite بارگذاری می‌شود.
* **کارایی:** کل داده یک بار در حافظه می‌آید، جستجو روی نمایهٔ یکدست‌شدهٔ متن انجام
  می‌شود و جدول به‌صورت مجازی رندر می‌شود. سنجش با ۵۳۲ پرونده: جستجو ۰٫۲۳ میلی‌ثانیه،
  رندر جدول ۷ میلی‌ثانیه، و تنها ۳۲ ردیف در DOM. کل بخش گزارش (۱۰ نمودار) هم
  روی همان ۵۳۲ پرونده بدون تأخیر محسوس رندر می‌شود.
